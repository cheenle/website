Agentic Engineering · 智能体工程

人的意图。
智能体的执行。现场的证据。

智能体工程的纪律，是构建一个「智能体可被信任去执行、而人保留唯一裁决权」的工程环境。VLSC 是从现场工程走到这里的，而不是相反。

01 · 命题

执行可以委托，判断不行

撑起本页的是三个主张，每一个都对照工件校验，而非观点。

角色变了

工程内循环，规格、实现、测试、审查、观测、回写 SDD——由智能体携带真实工具、在真实仓库与真实门禁下执行。

为什么是现在

因为智能体在行动前真的会加载契约。AGENTS.md、活体 SDD 与领域本体，从文档变成了运行时上下文。

FDE 仍然是门禁

现场纪律产出了值得复用的契约；它也保留了智能体永远不能代为签字的部分：PCB、台架、RF 安全、真实台站。

可证伪形式：一次现场事故变成一条 SDD 裁决，裁决变成一条机器可读约束，约束阻止智能体重新引入该事故。本页任何无法沿这条链回溯的主张，都不写，这条链在《三板斧》里被完整走了一遍。
02 · 分工

智能体跑循环，人握住三样东西

这条分界线不按任务大小或技能划分，而按「结果出错时谁负责」划分。

委托给智能体

规格→实现→测试→审查→观测→回写 SDD

智能体在动手前先读取约束注册表，按每条主张的性质选择对应的验证手段，并把结论写回它出发时所用的同一份契约。

人保留的三样

意图，这件事为何存在、什么算成功、什么刻意不做。
边界——架构裁决、安全不变量，以及智能体不得为了跑绿而交易掉的约束。
裁决——现有证据是否足以说一句「完成 / 已发布 / 安全」。
智能体承担执行，不承担问责。一次发射、一次发布、一句安全主张的责任，始终属于签署证据的那个具名的人。任何委托都不改变这一点，若想看只有一个具名负责人、没有团队时的版本，见《孤路我独行》。
03 · 前史

契约从前沿部署工程里来

本体不是 FDE 的第四个阶段，智能体工程也不使 FDE 退役。两个循环耦合，且各自握有否决权。

FDE 交付循环

Echo
现场证据→Delta
高风险验证→Product
稳定交付

Echo 观察真实台站与操作者；Delta 用可运行的垂直切片验证风险最高的假设；Product 把结果固化为可运维的边界、契约或可复用组件，而这就是日后能交给智能体的东西。

本体工程循环

范围→术语→关系→约束→验证

产品证据稳定词汇、暴露不变量；模型再为下一轮工作，无论人做还是智能体做，提供更干净的问题、更明确的边界，以及更少的偶然协议假设。

现场支持回路——FDE 实践 4

上报→分诊→分类→答复→实施→合入

支持链对自己迭代。每条 🐞 上报都带着分类（bug / feature / noise）落进 公开看板；分类即决策——noise 闭环、bug 自动排期、feature 等操作员，无人值守实施者产出受护栏保护的 unified diff 补丁，只落在隔离的 fde/<id> 分支，全套测试绿才提交。main 永不被触碰；合入仍是人的动作。回路的边界已从一条已答复工单移动到了一处已审查分支。

实践 4 延续这条前史：上面的 FDE 回路产出了智能体今天加载的契约；现场支持回路是同一套「判断 / 执行 / 证据」分工在用户所在之处的应用，完整机制见机制分册的现场回路一节。

智能体不能压缩的部分

硬件

PCB 制板与台架 bring-up。EFHW V3.0 设计与固件已完成；在实物板子存在之前，它的主张停留在设计目标。

RF 安全

真实电台上的 PTT 路径与发射权限。服务端测试通过，不等于客户端签字放行。

真实台站

在操作者自己的天线、波段条件与邻居环境下的现场验证。

发布

发布决策，以及什么可以被标注为「已发布」，因为这个标签是对一个人的承诺。

双向反馈：产品为模型修订提供证据；模型为下一轮现场循环提供语言、边界与能力问题，而现在这份上下文是由智能体在编辑前加载的。
04 · 机制摘要

Harness × Loop × Living SDD

Engineering 是把现场意图转化为可重复执行、可审查增量、可追溯证据和可复用资产的完整体系。

Harness

业务、技术和产品约束包围着由 Agent、工具、测试、部署与现场遥测组成的工程护栏与执行环境。

Loop

外层 Echo → Delta → Product 包含内层 Specify → Implement → Test → Review → Observe → Update SDD 工程闭环。

Living SDD

设计意图流向实现；代码、测试、部署和现场证据反向校准活的双向契约。

跨五个产品族：同一工程体系适配不同电台、协议、客户端、工作流、硬件门禁与证据边界。

05 · 生态地图

三条轨道，而不是一条人为流水线

硬件与运行目标不同，架构也不同；共享基础是控制权、媒体流、安全、可观测性与证据。

电台控制

MRRC Universal 提供基于 Hamlib 的广泛远控；MRRC FT-710 完成 Direct USB 垂直验证；MRRC Modern 通过 RadioBackend 与 RadioCapabilities 完成平台化。

Direct-IQ SDR

SunMRRC 负责 ExpertSDR 侧台站状态和 IQ/音频流；其客户端包括 Web 与原生 iOS 客户端 SunsdrMobile，后者不是独立产品族。

工作流 / RF 边缘

MRRC-FT8 协调时隙敏感的数字模式流程；EFHW 把执行活动推进到天线边缘，关注 RF 测量、舵机动作与限位安全。

07 · 工程杠杆

复用平面，而不是复用偶然实现

复用发生在显式架构平面，不意味着不同协议、设备或成熟度可以互换。

控制平面

控制意图、权威状态、控制租约（Control Lease）、能力发现和幂等协调。

媒体平面

音频、IQ、瀑布图、封帧、节奏、缓冲及传输丢失行为。

设备平面

电台后端、协议绑定、USB 端点、DSP 集成和 RF 执行器。

安全平面

PTT 联锁、超时回 RX、功率/行程限制、单所有者转换与故障隔离。

工作流平面

操作意图、定时 QSO、调谐搜索、重试、取消与恢复。

体验平面

Web/PWA/原生交互、反馈、控件、无障碍和移动端人体工学。

inherits

特化项保留已声明约束或契约。

consumes

客户端消费服务，但不拥有服务的系统边界。

implements

inspired-by

08 · 领域本体

本体在智能体动手之前被加载

不是文档习惯：同一套术语、边界与公理，被智能体上下文、编辑前门禁与人工审查三方消费。它仍然是一份由产品证据支撑的轻量双语契约，不是 RDF/OWL 部署、知识图数据库，也不是新增的运行框架。

本体概念 / 公理 消费方 真实锚点
Policy/Constraint：单一权威状态持有者、Serial 独占 Agent 运行时硬阻断 ft8 no-direct-serial——“rigctld is the sole serial owner”[AD-008]；ft710 / modern cat-direct-serial-io [AD-002]

RF 信号、IQ 采样、音频流、帧、频谱、SWR、频率和电平。

时间 / 工作流

时刻、区间、时隙、截止时间、工作流状态、QSO、取消和重试。

安全 / 可靠性

联锁、安全状态、超时、故障、不确定性、限制、恢复和监督。

证据 / 溯源

主张、来源工件、版本、测试方法、环境、结果和限制。

跨产品族安全不变量

  1. 权威状态所有者唯一。
    客户端可以投影或请求状态，但不能静默成为台站权威。
  2. TX 必须具备授权和安全上下文。
    发射请求需要有效权限路径、控制权/租约及适用联锁。
  3. 断线和超时收敛到 RX。
    控制丢失必须让台站趋向非发射安全状态。
  4. 命令不等于确认状态。
    请求的执行活动与观测到的状态报告始终分离。
  5. 不可检测故障不得声称已检测。
    没有传感器、信号或可测试观测路径，就不能主张检测能力。
  6. Profile 把概念绑定到产品。
    每个产品 Profile 声明能力、协议、客户端、安全约束和证据。
