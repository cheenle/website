# VLSC 全生态电影级宣传视频系列设计规格

**日期：** 2026-08-29

**状态：** 已完成设计讨论，待用户审阅书面规格

**制作平台：** MuleRun Studio + `ham.vlsc.net` 远端后期

**主视觉方向：** 未来工程纪录片

## 1. 目标与范围

为 VLSC 生态制作九个主题的中英文独立本地化长片，共 18 部成片。每部时长根据内容量控制在 25–35 分钟，总时长预计约 540 分钟。

九个主题为：

1. VLSC Portal 网站介绍片
2. MRRC
3. MRRC FT-710
4. SunMRRC
5. SunsdrMobile
6. EFHW
7. MRRC FT8
8. MRRC Modern
9. VLSC 全生态总片

为避免“Portal”和“全生态总片”含义混淆，实际交付口径如下：Portal 与另外七个项目网站各有一部独立介绍片，另加一部跨项目的 VLSC 全生态总片，共九个主题。Portal 介绍片聚焦门户定位、内容导航与品牌入口；全生态总片聚焦八个项目之间的技术路线和协同关系。

每个主题均交付中文和英文版本。两种语言共享核心电影镜头，但旁白结构、节奏、案例、界面演示、动态图形、字幕和片尾文字分别本地化，不采用逐句机械翻译。

## 2. 受众与传播目标

影片服务混合受众：

- 前半段面向普通科技爱好者和潜在用户，用故事、场景和清晰类比解释项目价值。
- 后半段面向资深火腿、射频工程师和软件开发者，深入架构、协议、数据流、安全机制、性能与工程取舍。

首要目标是建立 VLSC 生态的专业可信度与品牌影响力；第二目标是帮助观众准确理解每个项目的定位、使用方式及相互关系。

## 3. 创意原则

采用“未来工程纪录片”语言：Apple 发布片级产品摄影、工程剖视动画、真实操作演示和克制的全球通信史诗镜头相结合。

影片不使用贯穿式 AI 主持人。叙事由高质量纪录片旁白、产品与场景镜头、真实界面、动态图形、配乐和声音设计推动。

真实性规则：

- 真实网站、产品图片、界面、SDD、代码和项目文档优先。
- 缺乏实拍素材时允许生成概念场景，但不得虚构产品功能、接口、性能或使用结果。
- 在适当位置将生成场景标注为“概念可视化 / Concept Visualization”。
- 视频模型不生成承担信息传达作用的可读文字；术语、参数、标签和字幕统一在后期以原生矢量图层叠加。

## 4. 单片叙事结构

每部影片采用六幕结构，具体时长可随站点内容量调整：

1. **电影序章（1–2 分钟）**：从真实无线电需求或典型场景切入，以电影镜头建立情绪。
2. **问题与背景（3–5 分钟）**：解释传统方案限制、目标用户和项目缘起。
3. **产品与核心价值（5–7 分钟）**：展示真实界面、硬件和关键工作流程。
4. **系统架构深潜（8–12 分钟）**：讲解组件、协议、数据流、安全机制和工程决策。
5. **真实使用旅程（4–6 分钟）**：演示从部署到完成一次典型操作的完整流程。
6. **生态关系与终章（2–3 分钟）**：说明与其他 VLSC 项目的关系，以统一品牌主题收束。

全生态总片采用独立叙事：“用户需求 → 两条技术路线 → 八个解决方案 → 完整生态 → 未来方向”，不机械拼接或重复八部站点影片。

## 5. 视觉圣经

### 5.1 四类核心镜头

1. **产品英雄镜头**：微距材质、真实物理光照和缓慢机械运镜；不得生成错误接口或虚构铭牌。
2. **工程剖视与数据流**：使用统一图形语法解释信号链、协议、模块和状态变化。
3. **全球通信史诗**：地球、城市、户外远征和无线电传播用于章节开场与情绪高潮，不代替事实说明。
4. **真实界面与操作**：网站、应用和控制流程使用真实录屏；重构只用于提高清晰度和叙事效率。

### 5.2 色彩体系

- VLSC / Portal / MRRC / SunMRRC：青色与深石墨色
- MRRC FT-710 / SunsdrMobile：琥珀色与深石墨色
- EFHW：翡翠绿色与深石墨色
- MRRC FT8 / MRRC Modern：以各自网站现有品牌规范为准，并纳入统一石墨黑电影底色

所有站点共享字体层级、图形运动、字幕安全区、转场节奏和片尾结构，同时保留独立品牌色。

### 5.3 时间线标准

最终时间线按 4K UHD、16:9、24 fps 设计。Seedance 2.0 生成镜头最高为 1080p，因此不得宣传为原生 4K。生成镜头经质量增强后，与原生 4K 字幕、动态图形、界面录制及 GPT Image 2 素材在 4K 时间线中合成。

## 6. 10-Agent 制作组织

采用混合矩阵制：

1. Portal / 全生态 Agent
2. MRRC Agent
3. MRRC FT-710 Agent
4. SunMRRC Agent
5. SunsdrMobile Agent
6. EFHW Agent
7. MRRC FT8 Agent
8. MRRC Modern Agent
9. 总导演 Agent
10. 技术监制与终审 Agent

八个站点 Agent 负责各自资料研究、事实台账、脚本、分镜和章节制作。Portal / 全生态 Agent 同时承担总片主叙事，但不增加主题数量。总导演统一视觉圣经、镜头语言、音乐主题和品牌规范。技术监制负责事实核验、术语一致性、镜头质量、编码检测与最终验收。

Agent 之间不并发编辑同一事实台账或同一时间线。共享资产采用版本化只读发布；站点成果通过明确的阶段门禁进入总导演和技术监制流程。

## 7. 模型与生成策略

已在 MuleRun Studio 核实以下端点可用：

- `bytedance/seedance-2.0/text-to-video`
- `bytedance/seedance-2.0/image-to-video`
- `bytedance/seedance-2.0/reference-to-video`
- `openai/gpt-image-2/generation`
- `openai/gpt-image-2/edit`
- `google/veo3/generation`
- Kling V3 与 Kling V3 Omni 系列
- Wan 2.6 系列
- MiniMax Speech 2.8 HD
- MiniMax Music 2.5

模型路由规则：

- Seedance 2.0 是主视频模型，优先使用参考图生视频和参考生视频维持产品与风格一致性。
- GPT Image 2 以 4K 模式制作关键帧、工程剖视图、产品英雄图、海报及连续性参考。
- 关键镜头至少生成三个候选版本。
- Seedance 结果不合格时，先调整参考帧和提示词；持续失败后由 Veo 3 或 Kling V3 Omni 重新竞标。
- Wan 2.6 作为多镜头和辅助生成选项。
- 配音使用当前可用的最高质量多语言语音端点，首选 MiniMax Speech 2.8 HD；正式批量生成前通过双语声音试镜锁定音色。
- 配乐使用原创生成音乐，首选 MiniMax Music 2.5，并保留每段音乐的提示词和授权记录。

## 8. 画面构成与生成规模

每部影片预计由以下素材构成：

- 20–30% AI 电影化视频
- 25–35% 真实网站、应用、设备与操作演示
- 25–35% 原生 4K 工程动画、架构图和数据可视化
- 10–20% 产品照片、文档、地图及电影化静态资产

全系列预计需要约 650–1,000 个最终验收的生成镜头。关键镜头生成多个候选；普通转场和辅助镜头减少候选数量，以在不降低可见质量的前提下提升速度。

## 9. 制作数据流

1. 从网站、SDD、代码、图片和现有视频中建立可追溯事实台账。
2. 编写中英文独立脚本、时间轴和镜头清单。
3. 生成并批准风格帧、角色为空的场景规范和产品连续性参考。
4. 通过 MuleRun Studio 并行生成关键帧、视频、旁白和配乐。
5. 将结果下载至 `ham.vlsc.net`，执行校验、代理转码、章节合成、混音、字幕和编码。
6. 逐章验收后生成整片母版及发布版本。
7. 生成制作报告、哈希清单和可追溯模型记录。

每项生成资产记录：站点、章节、镜头编号、语言、提示词、模型端点、参数、种子、生成时间、源文件哈希、事实来源和审核状态。

## 10. 远端算力与存储

`ham.vlsc.net` 已验证具备 16 核 CPU、59 GiB RAM、FFmpeg，以及约 582 GB 的 `/home` 可用空间。服务器没有 NVIDIA GPU，因此其职责限定为下载、校验、代理转码、CPU/可用硬件编码、合成、混音、字幕和交付打包；生成模型推理由 MuleRun Studio 云端完成。

远端按站点分批处理：

1. 原始素材进入冷存储区。
2. 低码率代理用于审片与剪辑。
3. 章节通过后生成中间母版。
4. 成片通过后清理可再生成缓存。
5. 永久保留源素材、工程描述、脚本、字幕、最终音频与母版。

目标峰值磁盘占用为 350–450 GB。若实测超过 450 GB，暂停新素材下载并先归档已完成站点，不能以删除唯一源文件的方式释放空间。

本地仓库只保存文本清单、自动化脚本和低码率审片索引，不提交大型媒体文件。本任务不得覆盖、重置或纳入当前工作区已有的未提交修改。

## 11. 质量门禁与异常处理

阶段门禁依次为：

1. 事实锁定
2. 脚本锁定
3. 风格帧锁定
4. 章节粗剪
5. 语言审校
6. 技术终审
7. 母版批准

镜头评分维度：

- 技术与产品准确性
- 时间连续性和物理合理性
- 品牌及设备一致性
- 构图、光影和叙事价值
- 手部、接口、文字、天线结构等伪影

关键维度不合格即拒绝。生成服务发生网络或限流错误时，调度器采用带抖动的指数退避并保留任务状态；内容质量失败则更换提示词、参考帧或模型。单个镜头失败只重跑该镜头，单章失败只重做该章。

所有技术陈述必须链接至网站、仓库文档、代码、SDD 或用户提供资料。存在冲突时，以最新的一手项目资料为准并记录裁决；无法核实的数据不进入成片。

## 12. 音频与本地化

- 中英文分别维护术语表、读音表、脚本和字幕。
- 旁白采用自然纪录片表达，不逐句翻译。
- 配乐为原创纯音乐，不使用未经许可的录音或影视配乐。
- 对话清晰度、动态范围、响度和真峰值均自动检测。
- 最终字幕由可审查脚本生成并人工式校验，不直接使用自动识别字幕作为交付稿。
- 品牌名、呼号、协议名、设备型号和单位必须逐项验证读音与拼写。

## 13. 验收标准

每部影片必须满足：

- 时长 25–35 分钟
- 中文和英文各一部独立本地化版本
- 4K UHD、16:9、24 fps 时间线
- 无水印、黑帧、断音、缺失媒体或损坏编码
- 响度目标约为 -14 LUFS，并限制真峰值
- 字幕不越过安全区，时间轴与语音同步
- 所有关键技术陈述可追溯
- AI 概念画面不虚构功能，并按规则标注
- 跨片品牌、术语、色彩和片尾结构一致

## 14. 交付物

每个主题交付：

- 中文和英文 4K 高码率归档母版
- 中文和英文 4K H.265 发布版
- 中文和英文 1080p H.264 兼容版
- 中文和英文 SRT、WebVTT 字幕
- 独立旁白、配乐、音效和最终混音轨
- 章节缩略图、海报和标题图
- 中英文脚本、事实台账、镜头表、模型参数与种子
- 素材来源、授权与概念可视化记录
- SHA-256 校验文件与制作报告

具体归档封装格式在样片阶段根据远端编码能力测试确定；归档母版优先选择视觉无损或近无损、可被标准后期软件可靠读取的格式，发布版固定提供 H.265 与 H.264。

## 15. 最快执行顺序

1. **事实与资产冻结：** 10 个 Agent 并行完成资料盘点、事实台账和术语库。
2. **90 秒双语 4K 样片：** 同时覆盖产品英雄镜头、Seedance 场景、GPT Image 2 工程图、真实界面、双语旁白、原创配乐与最终调色。
3. **样片定标：** 锁定提示词模板、音色、音乐主题、字幕、调色和验收阈值。
4. **18 部影片并行生产：** 站点按章节推进；章节一旦通过即可在远端合成，不等待全片素材齐备。
5. **终审与交付：** 完成事实、语言、音画、编码和跨片一致性检查。

并发调度最多维持十条逻辑工作流；实际同时发起的 MuleRun 请求数服从端点限流和服务稳定性。任何提高并发度的调整都不得绕过质量门禁。

## 16. 明确不在本规格范围内的内容

- 竖屏短视频、社交平台切片和广告投放计划
- 真人主持人或真人实拍摄制
- 为影片虚构尚未实现的产品路线图
- 修改八个网站的产品功能或网站内容
- 将大型媒体二进制直接提交到当前 Git 仓库

这些项目可在长片体系稳定后另行设计，不阻塞本次 18 部影片制作。
