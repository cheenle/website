01 · 双循环

交付与知识共同演化

领域本体不是 FDE 的第四阶段。产品交付和知识工程是两个相互校准、但边界独立的循环。

FDE 交付循环

Echo
现场证据→Delta
高风险验证→Product
稳定交付

Echo 观察实际台站与操作员；Delta 用可运行的垂直切片验证最高风险假设；Product 把结果固化为可运维边界、契约或组件。

本体工程循环

范围→术语→关系→约束→验证

产品证据稳定词汇并暴露不变量；模型再为后续工程提供更好的问题、边界和更少的协议偶合。

双向反馈：产品为本体修订提供证据；本体为下一轮现场工程提供语言、边界和能力问题。
02 · 生态地图

三条轨道，而不是一条人为流水线

硬件与运行目标不同，架构也不同；共享基础是控制权、媒体流、安全、可观测性与证据。

电台控制

MRRC Universal 提供基于 Hamlib 的广泛远控；MRRC FT-710 完成 Direct USB 垂直验证；MRRC Modern 通过 RadioBackend 与 RadioCapabilities 完成平台化。

Direct-IQ SDR

SunMRRC 负责 ExpertSDR 侧台站状态和 IQ/音频流；其客户端包括 Web 与原生 iOS 客户端 SunsdrMobile，后者不是独立产品族。

工作流 / RF 边缘

MRRC-FT8 协调时隙敏感的数字模式流程；EFHW 把执行活动推进到天线边缘，关注 RF 测量、舵机动作与限位安全。

04 · 工程杠杆

复用平面，而不是复用偶然实现

复用发生在显式架构平面，不意味着不同协议、设备或成熟度可以互换。

控制平面

控制意图、权威状态、控制租约（Control Lease）、能力发现和幂等协调。

媒体平面

音频、IQ、瀑布图、封帧、节奏、缓冲及传输丢失行为。

设备平面

电台后端、协议绑定、USB 端点、DSP 集成和 RF 执行器。

安全平面

PTT 联锁、超时回 RX、功率/行程限制、单所有者转换与故障隔离。

工作流平面

操作意图、定时 QSO、调谐搜索、重试、取消与恢复。

体验平面

Web/PWA/原生交互、反馈、控件、无障碍和移动端人体工学。

inherits

特化项保留已声明约束或契约。

consumes

客户端消费服务，但不拥有服务的系统边界。

implements

组件实现接口、能力或协议绑定。

inspired-by

证据影响后续设计，但不暗示代码或契约继承。

05 · Engineering System

Harness × Loop × Living SDD

Engineering 是把现场意图转化为可重复执行、可审查增量、可追溯证据和可复用资产的完整体系。

Harness

业务、技术和产品约束包围着由 Agent、工具、测试、部署与现场遥测组成的工程护栏与执行环境。

Loop

外层 Echo → Delta → Product 包含内层 Specify → Implement → Test → Review → Observe → Update SDD 工程闭环。

Living SDD

设计意图流向实现；代码、测试、部署和现场证据反向校准活的双向契约。

跨五个产品族：同一工程体系适配不同电台、协议、客户端、工作流、硬件门禁与证据边界。

06 · 领域本体

轻量、模块化的远程业余无线电模型

领域本体（Domain Ontology）是由产品证据支撑的双语工程契约；它不是 RDF/OWL 部署、知识图数据库或新增运行框架。

主体 Agent

拥有权限和责任的操作员、管理员、维护者或自动控制器。

物理实体 Physical Entity

电台、天线、调谐器、接口、传感器、执行器和台站环境。

软件系统 Software System

台站服务、客户端、后端、适配器、解码器、DSP 或持久化组件。

活动 / 过程 Activity

执行活动、观测活动、发射、接收、调谐、解码、同步与恢复。

信息对象 Information Object

控制意图、状态报告、帧、采样、事件、QSO、Profile 或证据记录。

能力 / 功能 Capability

调谐、PTT、模式、音频、IQ 流、解码、匹配和测量。

策略 / 约束 Policy

授权、租约、超时、联锁、功率限制、时间窗与安全状态规则。

证据 / 溯源 Evidence

支撑成熟度主张的来源、版本、环境、方法、结果、日期和限制。

本体模块

身份 / 权限

主体、凭据、角色、许可、控制租约、所有者与委派。

台站 / 设备

台站、电台、收发机、天线、调谐器、传感器与执行器。

功能 / 服务

能力、服务、端点、依赖、可用性和降级。

命令 / 执行 / 观测

意图、请求变更、物理/软件活动、测量结果和状态报告。

协议 / 传输

协议绑定、设备适配器、CAT、rigctld、WebSocket、串口、USB 和数据包。

信号 / 媒体 / 测量

RF 信号、IQ 采样、音频流、帧、频谱、SWR、频率和电平。

时间 / 工作流

时刻、区间、时隙、截止时间、工作流状态、QSO、取消和重试。

安全 / 可靠性

联锁、安全状态、超时、故障、不确定性、限制、恢复和监督。

证据 / 溯源

主张、来源工件、版本、测试方法、环境、结果和限制。

跨产品族安全不变量

  1. 权威状态所有者唯一。
    客户端可以投影或请求状态，但不能静默成为台站权威。
  2. TX 必须具备授权和安全上下文。
    发射请求需要有效权限路径、控制权/租约及适用联锁。
  3. 断线和超时收敛到 RX。
    控制丢失必须让台站趋向非发射安全状态。
  4. 命令不等于确认状态。
    请求的执行活动与观测到的状态报告始终分离。
  5. 不可检测故障不得声称已检测。
    没有传感器、信号或可测试观测路径，就不能主张检测能力。
  6. Profile 把概念绑定到产品。
    每个产品 Profile 声明能力、协议、客户端、安全约束和证据。

12 个能力问题（Competency Questions）
  1. 哪个软件系统拥有指定电台的权威状态？
  2. 哪个主体当前持有发射控制租约？
  3. 哪个控制意图请求了执行活动，哪次观测确认了结果？
  4. 哪个设备适配器为特定设备 Profile 实现某项能力？
  5. 哪个协议绑定承载控制、媒体或测量数据？
  6. 什么事件迫使系统收敛到 RX 或其他安全状态？
  7. 哪些客户端消费产品服务，但不构成独立产品族？
  8. 哪个 RF 信号形成了哪些采样、流和帧？
  9. 哪个时间区间或截止时间约束一次发射？
  10. 哪项安全主张具备真实传感器或观测路径？
  11. 哪个证据工件支撑某成熟度标签，适用于哪个版本和环境？
  12. 哪些资产属于继承、消费、实现或仅受前作启发？
有证据支撑的演化时间线
  • 通用控制：基于 Hamlib 的运行建立广泛电台控制和台站状态模式。
  • FT-710 垂直切片：Direct USB CAT/音频验证高风险端到端路径。
  • Modern 平台：FT-710 假设被提炼为后端与能力抽象，并扩展到 IC Profile。
  • Direct-IQ 轨道：SunMRRC 分离台站权威与媒体契约；SunsdrMobile 以原生客户端消费服务。
  • 工作流与边缘：MRRC-FT8 加入定时运行语义；EFHW 将模型扩展到物理 RF 测量与执行。
  • 领域本体：只有当概念和约束跨产品出现证据后，才进行归纳。
