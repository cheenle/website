推断 · 选型单位

旗舰模型买「方向」，性价比模型买「执行」，长上下文变体买「专项」，harness 买「工作方式」。同一个模型装进不同 harness，会呈现完全不同的任务画像：gpt-5.6 在 codex 是攻坚队，在 pi 是发布流水线。所以选型单位是「模型 × harness × 任务」三元组，从来不是模型本身。

03 · 公开评测

两种数字，分层存放

独立测评和厂商公告是两种不同性质的证据：既不混在一起求平均，也不并列放进同一列。

独立测评

  • Artificial Analysis 智能指数：Kimi K3 57、Qwen3.8-Max 56。
  • LMArena——Gemini 3 Pro 1501 Elo，首个突破 1500 的模型。
  • Code Arena——GLM-5.2 编程盲测 1595 分，开源权重模型第一。

厂商口径

  • DeepSeek-V4-Pro 在 Codeforces 得 3206。
  • Qwen3.8-Flash 宣称在 SWE-bench Pro 上领先 Opus 4.6 达 9.1 分。
事实 · 性价比档是最扎实的公开叙事

V4-Flash（OpenRouter 每百万 $0.14 / $0.27）、Qwen3.8-Flash（官方口径为其三分之一价）、GPT-5.6 Luna、Gemini 3.1 Flash-Lite——全挤在「日常工程负担得起」这同一个生态位上。这种拥挤与本地实测的用量互相印证：过去几个月，性价比档吃下了日常工作的绝大部分。

论点 · 只有你自己的日志在测量你的工作

公开榜单回答的是「这个模型总体上有多好」，回答不了「这个模型在我的任务、我的 harness、我的代码库上有多好」。能回答后一个问题的工具只有一件：你自己的用量日志，这正是本系列一直坚持为它做快照、加标注的原因。

04 · 路由标签

日志里的名字不是模型实体

把日志里的标识当路由标签看，别当能力实体看。

big-pickle

OpenCode 官方承认的隐身模型。它是一个真实端点，名字故意不透露任何信息：任何针对它的评测，评的都是一个未知量。

code-supernova-1-million

2025 年的隐身营销名。原渠道已经下架，这个标签再也对应不到任何实体，日志里留下的，是一条指向已退役别名的记录。

kimi-for-coding

套餐 API 的别名。同样带着这个标签的两次调用，可能在不同时间由不同的底层模型响应，所以相邻调用之间不构成受控对比。

推断 · 为什么这对测量重要

年鉴里的每条结论都建立在这类标签之上。这不会让结论失效，但会给它划出边界：「这个标签这周用得更多」是关于路由的陈述，「这个模型变强了」是关于能力的陈述。前者能从日志里测出来，后者不能。一旦把两者混为一谈，一份用量报告就会悄悄变成一份评测榜单。
