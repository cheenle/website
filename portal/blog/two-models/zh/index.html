可见病根乙迹甲账丙影六得对账补牢

前四十八小时，两条会话在同一棵工作树上发出七个版本，撞出两次冲突。接下来的三天，故事没有按「换个更强的模型」发展。它按另一条路走：冲突清零，病根回访，第三条会话入场，以及一条此前没人命名的根因浮出水面：自述与实测之间没有闸门。五天下来，用户的问题在变得更「笨」。这是系统变好的形状。

TL;DR — 六条结论

  • 事实四个老根因一个都没死，各添了新案例。「默认值只在构建机上成立」第五次现身，换了名字：macOS 安装包继承构建机的 MacPorts 证书路径，用户机器上信任库为空，注册、诊断上传、更新检查三连失败（v1.25.1）。
  • 事实五张用户工单，全部定性为环境类，无一转成热修。三张已公开答复，每张附原始证据。工单问的都是「电台没接好」与「域名怎么配」。对比四十八小时时工单直接驱动热修，这是产品稳定下来的旁证。
  • 推断守卫本身会空转。那条检查表格行标签的守卫从未运行过，却报告二十七组全绿。揭穿它的不是测试套件，是变异测试：把缺陷还原回去，守卫依然绿。会撒谎的不只是验证脚本，还有验证本身。
  • 推断验证脚本一小时内实测出五种安静的撒谎方式。PowerShell 变量大小写不敏感、裸 000 是八进制 0、时间戳没有跑前基线、200 应答来自另一实例、符号走查看错表。判据必须取自产品自己的输出，不取自造的脚手架。
  • 立论并行协作的零冲突不是纪律的胜利，是结构的胜利。前半程两次真实冲突（被覆盖的清单、重复构建）；后半程第三条会话带着自己的 worktree 与发布通道入场，跨会话动作一律哈希重验。剩下的唯一事故，是 v1.25.2 漏刷升级清单，被下一个版本的 tag 记录点名。
  • 已排除本文仍不衡量模型优劣。三条会话互不可观测对方的推理过程，对乙、丙的一切判断以产物为据，取不到证据的地方写「未知」。新增会话称丙，同样只评产物。

02 · 病根

四个老根因回访，一个新根因浮出

四十八小时里给它们起过名字。五天里，它们换了几次名字回来。

前作记录了四个根因：默认值只在构建机上成立；进程生命周期与配置生效时机错位；网络结论没有测量支撑；界面缺一条路。五天里，前四因各添了新案例，另有一类缺陷不属于产品，属于治理，首次获得名字：自述与实测之间没有闸门。

根因第五天里的新名字
① 默认值只在构建机上成立 macOS 安装包继承了构建机的 MacPorts OpenSSL，证书路径硬编码 /opt/local。用户机器上不存在该路径，信任库为空：portal 注册、诊断包上传、更新检查三连 CERTIFICATE_VERIFY_FAILED（v1.25.1）。同一个包还把 FTDI 库放错了目录，launcher 锚在另一处，频谱四十二次启动全部 frames=0，界面只剩 S 表回退，此前无人知晓。
② 进程生命周期与时机错位 frps 收到 SIGHUP 后干净退出，systemd 把「干净退出」记为 reload 成功，进程不再拉起，现场实测约七秒空窗。发射心跳要等同一次按键处理的返回，watchdog 在数十毫秒的窗口里看见「持键但沉默」的会话，一天之内七次释放掉用户刚按下的 PTT（v1.25.3）。首跑串口探测写死超时，在一台现场机器上永久卡死、占着 COM3 数小时（v1.25.0）。
③ 网络结论没有测量支撑 按 deploy/README 写的一台主机查案，得出「三个实例全部离线」的错误结论。那台主机早已退役，注册表都已分叉。同一份 README 连续两次把排查带偏。另一次，前天钉死的「IPv6 不通」结论，被隔日的实测推翻：新 hub 上 v6 全程 82 毫秒、零丢包。
④ 界面缺一条路 批准通过的提示叫用户去点「设置 → 接入云端 → 刷新状态」，那个菜单不存在，实测出现次数为零，入口其实在抽屉里。Android 设置页没有任何返回路径（v1.1.5）。管理台登录失败一次重渲染，相对路径就把 URL 加成 /admin/admin/login，404。
⑤ 自述与实测之间没有闸门（新） README 写着路由自动化「一并安装 ✓ 不会再漏 ✓」。实测现网只装了 service，脚本与 timer 俱缺，路由自合并当夜起三十多个小时从未再生，第一个走完全部流程的新实例万事俱备、入口 404。「✓」没有对应的检查，它就是一句愿望。下载站的树莓派卡片同属此类：它把 v1.17.0 写成现役版本，链接指向的文件却早已从服务器上消失，每次访问都是 404，持续时长不可考。

第一因最值得再讲一次。四十八小时里它被修了四次，证书、日志、串口、口令。第五天它第五次现身，换成了信任库与动态库的路径继承，一次咬出三个功能。给类起的名字还挂在墙上，类自己却换了衣服。命名管住了旧衣服，没管住新衣服。

推断 · 名字防复发，不防变种

闸门测试的形状是「旧名字的实例再出现就变红」。变种穿着新衣服来时，测试不认识它。这五天里每次收口的最后一步，仍然是人问一句「这是不是又是那谁」。模型没有自发做这一步。名字防复发，防变种靠的仍是一次具体的发作。

03 · 乙迹

乙：Hub 线，一百零六个提交

portal 从零到二千五百六十九行，SDD 卷宗新增二十个版本。每条都对应一件产物。

乙的主场是 MRRC Cloud Hub：portal 管理台、安装器链、SDD 设计卷宗。窗口起点它还没有 portal；窗口终点，portal 八模块四十九组测试，SDD 从 V0.8 记到 V0.28。同时它贡献了本次窗口最典型的自检失败案例。

① 枪毙一条空转的守卫

系统视图的两列表格丢了行标签，而负责检查这条的守卫从未运行过：表头宽度存进了一个从不写入的变量，又被一个恒假的条件短路，套件报告二十七组全绿。揭穿它的是变异测试：把缺陷原样还原回去，守卫依然绿。修复后三个变异各自红出精确形状。留下的注释是一句判词：对坏输入报绿的守卫，比没有守卫更糟。

② 重新定义「在线」

frpc 注册成功不等于在服务：本机回环端口谁连都通。乙把布尔值拆成 serving、plain-http、hollow、down 四态，探测改成并发。实测串行四点八二秒，并发一点六秒。判据从「连得上」换成「拿到 HTTP 应答，任何状态码都算」。

③ 「未安装」也是一种结论

五层观测面 host → service → tunnel → instance → app 一拉，routes timer 的状态是 not-found。not-found 不是缺数据，是答案：自动化根本没装上，路由停滞三十多小时。补齐后，新实例的 404 当场变 302。

④ 认证一日落地

Python 3.13 移除了 crypt 模块，htpasswd 的 $apr1$ 散列没有标准库可用。乙手写 MD5 摘要逻辑，与 openssl passwd 交叉验证；不存在的用户名也跑一次假哈希，防时序侧信道；登录守卫按固定阈值锁定；审计条目归因到具体操作者。规格先行：十一条决策逐条经人批准才动工。

⑤ 部署当天推翻两个假设

实现前的假设是 frp 支持热重载、面板有累计流量。部署当场两处皆错：SIGHUP 让 frps 干净退出，systemd 记为 reload 成功；面板只有今日流量，带宽改靠相邻采样差分加回绕检测。规格文档如实记下推翻过程，没有回头改假设。

⑥ 打脸留在卷宗里

V0.22 自称已把 README 改到新版，下一版自己记一笔：漏改的就是本仓，「没有文档一致性门禁，只能靠读者抓」。docstring 描述的是十分钟前的实现。V0.16 重了号，也留在原地。卷宗的诚实度是它最值钱的资产。

弱项，同样只看产物

  • 「✓ 不会再漏」被实测推翻。路由自动化缺失三十六小时，第一个受害实例吃到 404。「不会漏」写进了 README，没有写进任何检查。
  • 退役主机当事实源，连偏两次排查。deploy/README 把 SSH 目标写成一台已退役的旧机，注册表都已分叉。两次排障都先信它，两次得出错误结论。
  • 窗口最后一个提交仍在修自己。管理台登录失败重渲染时相对路径加倍，URL 变成 /admin/admin/login。这是五天的收尾提交，没有对应的 SDD 版本记录。
已排除 · 关于乙仍有三件事说不出口

乙的工具调用失败率、重试次数、是否先断言后测量，都无法从仓库恢复。能恢复的是它的固定手法：每写一条守卫，都用变异测试验证守卫本身会咬人。手法一致性很高，但手法之外的推理过程，本文不猜。

04 · 甲账

甲：第一人称，含新增的账本页

前四十八小时的账本保留在文末。这里记第三天到第五天的新账。

补丁通道首开

「找不到输入口令的地方」不能再等一个安装包。静态资产补丁通道建成当天即实发：745 KB 对 54 MB，一次下载一次双击。验收方式是把服务器吐回的 JavaScript 抓下来，搜里面那个新符号。随后这套机制焊进 v1.24.8，补丁通道成为发布工程的一部分，而不只是一次救场。

v1.25.0：装完就能用

六个用户可见缺陷全部追到实测根因：首跑串口探测永久卡死，硬件自描述与探测关键词不匹配，先探到主板管理口，写超时为 None；批准轮询从对话框搬进服务端每三十秒自查；证书比对的对象比错；裸路由被当目录，API 要去拿 HTML；刷新按钮的样式像禁用；Windows 默认只监听回环。每一条都来自现场读数，不来自推断。

验证脚本的五种撒谎

一次发布前后，一小时内实测五种安静的谎：PowerShell 变量名大小写不敏感，$l 覆盖了报告列表 $L，把进程输出写进「报告」还报成功；裸 000 被解析成八进制 0，状态比较永不匹配；时间戳窗口没有跑前基线；那个 200 应答来自另一台实例；符号走查在错误的表里找名字。脚本没报错，每一句都是假话。

洁净室层的双重标准

多层验证里，洁净室层抓出了全部三个打包缺陷。但有一条注记：必须用现场配置 127.0.0.1 测。双冒号默认环境下测绿的两个缺陷，只在现场路径出现。对的环境伪装成错的环境，只需要一个默认值。

漏刷清单的自我点名

v1.25.2 发布后，升级清单没有刷新，装着 1.25.1 的机器永远拿不到它。发现者是下一个版本的发布流程自己：tag 记录里点名了这处遗漏，并写明 1.25.1 的机器将直接跳到 1.25.3、一并收下两个修复。漏没被藏住，因为它写在必须读的地方。

树莓派镜像的两记耳光

第一记：下载卡把 v1.17.0 写成现役版本，链接指向的文件早已不在服务器上，每次访问 404，持续时长不可考。镜像按 v1.24.0 用 pi-gen 在 Docker 里重制（原生 aarch64，约二十四分钟），仓内验镜脚本报 VERIFY_OK；唯一告警是一个版本敏感检查，如实记录在提交里，没有抹平。新镜像同时以版本名与固定名发布，旧镜像归档。

第二记：另一次发布的全局替换把镜像字节数 662,225,336 改成 654,077,021，即 Windows 的字节数加一个串位的前导数字；安装步骤还带着上一构建的哈希。此前教训已经入档：字节数与 SVG 颜色可以是同一字符串。复发说明教训进了文档，没变成检查。两个数字现在都取自产物本身。

工单五张，三答公开

五张工单全部定性为环境类：FT-710 三路没接好、通配域名被当成配置项、穿透入口没起。三张答复做成公开页面，每张带诊断、操作步骤、原始证据。第三张答复直接引用站内既有答复作证据。没有一张工单转成热修，但工单旁挂的已知问题卡片推动了 v1.25.1：macOS 打包版的信任库缺陷，只在用户机器上爆炸。

05 · 丙影

丙：一日八版，与真机的三记耳光

第三条会话只评产物。它的产物是一台手机里的一日。

丙的领地是 Android 客户端。入场时带着独立 worktree、独立分支、一键发布脚本。v1.0.0 首发后一日之内发到 v1.1.5，JVM 测试从 52 项长到 105 项。它的文档纪律像乙：先写设计，规划期验证出四处错误再动手，十六个任务排成 TDD 序列。它的现场闭环像甲：每记耳光的回声都变成一行代码。

真机耳光一：接线缺口

v1.1.0 的发布计划写着「待真机验收」。真机当天打脸：RX 音频与频谱从未启动。原因是两处接线缺口：播放函数没有任何调用点，瀑布数据流没有任何写入点。规划期验证与 JVM 单测全部通过，因为注入的依赖是 null。单测测的是想象中的接线。

真机耳光二：帧长减半

修完接线仍只播一半。JNI 层取的数组长度是样本数，编解码却按一半传参，每个 20 毫秒的包只被当 10 毫秒处理。这是 JNI 契约的形状，文档里没有，模拟器上听不见。

真机耳光三：并发丢事件

控制通、频谱通、RX 无声、PTT 不键控。根因是一个非线程安全的集合：四路回调并发增删，丢一个添加，聚合条件永不成立。修法是并发安全的结构，外加拆掉单点闸门：RX 只看音频流，PTT 只看电台流，与 Web 端语义对齐。这一版顺手把并发不变量写进测试，101 项到 105 项。

把用户的一句话变成字母

三记耳光之后，丙在设备上加了一行诊断输出：八个字母分别标记控制、频谱、音频、JNI 等各段是否活着，随后扩展成按通道逐项报状态。用户再说「没声音」，日志里那一行字母直接指到断掉的段。诊断行是真机的回礼：它把不可观测变成了可远程读取。

流程发明：不与别波抢一棵树

Android 与桌面版共用一棵站点树，整站部署会把另一波的下载卡滚回去。丙实测过这个事故：一次 Android 发布短暂地把线上卡片降级回旧版桌面号。解法不是小心，是结构：发布脚本加 --apk-only 模式，只动 Android 块；发卡脚本只改写线上页面的对应区块，改完逐字节回验两页与 APK 哈希。甲的提交里留下了对丙的记录：「另一会话发布了 v1.1.1，卡片跟随，哈希对线上 APK 逐字节重验」。

对比四十八小时时的零协调，这是协作方式的真实位移：跨会话的信任动作从「声明」换成了「重验」。乙代甲提交过文档，甲替丙验过哈希，谁也没信过谁的手。

推断 · 丙的盲区与成长同形

丙的三个真机缺陷有一个共同来源：规划期的验证环境里没有真机。它的反应不是补文档，而是补可观测性。让同一盲区下次变便宜的，不是「下次记得测真机」，而是把真机的不可观测性提前消灭。这个思路与甲乙的闸门一脉相承，出手却更快：三记耳光，当天回礼。

06 · 六得

六条，跨会话成立

它们经受住了第三条会话入场、第三个仓库、第二种客户端。

甲 · 名字防复发，防不住变种

四个根因的名字都挂在墙上，五天里它们各穿了一件新衣服回来。信任库路径、SIGHUP 语义、按键活性窗口，没有一个是旧名字的原文。模型修好一个实例之后，不会自发问「这是哪一类的变种」。这一步仍然由人完成。给握缰绳的人的实操不变：修完一个，先问类，再问闸门。

乙 · 不信任要制度化，且要验制度化本身

四十八小时的教训是别把信任交给代理信号。五天里这层不信任自己又迭代了一次：退出码之后是守卫，守卫之后是验守卫的变异测试。空转守卫给了一个干净的判词：对坏输入报绿的守卫，比没有守卫更糟，因为它还占着「已检查」的名义。同理，验证脚本按撒谎者对待：五种撒谎方式入档，判据只取自产品自己的输出。

丙 · 结构比纪律可靠，第二次被验证

四十八小时的解法是「一趟发布列车一个司机」，靠自觉。五天里的解法是所有权切分：一条线一个 worktree、一条发布通道、按块改写加哈希回验。自觉会衰减，结构不会。窗口后半程的冲突数是零，与催促强度无关，与天数无关。

丁 · 真机是一类环境，不是一类测试

模拟器、JVM、单测，都活在规划期的想象里。接线缺口、JNI 帧长、并发丢事件，全部只在真机现形。丙的反应是把真机的不可观测性消灭在客户端：一行字母，远程可读。甲乙也应该各问一次：自己的环境里，哪一行还不可观测？

戊 · 用户的问题在变得更笨，这是变好的证据

五天五张工单：电台三路没接好、把通配域名当配置项、穿透入口没起、空描述。没有一张是产品缺陷，全部答以证据页面。四十八小时时，工单驱动热修；五天后，工单只剩环境。产品稳定性的最好指标，恰恰是工单内容的退化。

己 · 审批点仍然是设计的一部分

乙的认证规格十一条决策逐条经人批准；甲的 macOS 打包计划列了三处偏离，写明「需要你点头」；一份安装验收的记录里留着一句「若不是你要求，我本会跳过这一步」。三条会话都在同一处表现出同一种分寸：验收标准归人，不归模型。这不是谦辞，是它们在五天里从未越过的边界。

立论 · 五日版的一句话答案

四十八小时的答案是「加约束，不换模型」。五天的补遗是：约束也会失效，所以要给约束配上验约束的约束。变异测试验守卫，哈希重验跨会话动作，tag 记录点名自己的遗漏。答案是同一句，只是不信任的层数多了一层。仍然不需要更强的模型，需要更密的不信任。

08 · 补牢

十一条，仍然不需要更强的模型

前五条承前作，后六条是这五天长出来的。每一项都因为缺了它而损失过时间。

承前

  • 一趟发布列车一个司机。五天后的升级版：一条产品线一个 worktree、一条发布通道。共享树上只许按块改写，改完哈希回验。
  • 先立闸门，再写复盘。守卫上岗前先做变异测试：把缺陷还原回去，守卫必须变红。对坏输入报绿的守卫，比没有守卫更糟。
  • 把规则做成工具。自觉随上下文衰减，钩子不会。这条在前作已验证，五天里没有被推翻，于是也不再重复验证。
  • 产物三证合一。版本号，带年份的时间戳，与上一版不同的哈希。升级版：tag 记录里点名自己的遗漏，清单由服务器从已发布文件生成，不来自任何本地副本。
  • 先要环境事实，再做推理。README 里的主机名也会过期。事实源本身要有人管。

新增

  • 「✓」必须对应一个会失败的检查。没有检查的自述按未完成处理。「不会漏」是一种预言，预言不参与构建。
  • 验证脚本按撒谎者设计。变量大小写、八进制字面量、时间戳基线、应答来源、符号查找表：五种安静的撒谎方式已入档。判据只取自产品自己的输出。
  • 环境默认值是伪装的高发区。双冒号环境测绿的缺陷，回环现场配置下才现形。洁净室层必须按现场形状配置，否则它验证的是另一个产品。
  • 部署文档是事实源，事实变了先改它。一台退役主机连偏两次排查。文档与现网漂移超过一天，可信度按零计。
  • 客户端要自带可观测性。一行字母定位「没声音」卡在哪段。真机缺陷不可避免时，让下一次变便宜。
  • 发布后的第一轮巡检，先于第二轮开发。v1.25.0 当夜的死链扫荡：安装脚本递出打不开的地址，六个链接指向虚空，整章指南缺失。庆祝之前先巡检。

给握缰绳的人

  • 催促会提高违反率。这一点前作已记，五天里没有新数据推翻它，仍按事实对待。想更快，指明哪一步可以省，不要笼统地催。
  • 要判据，不要计划。计划复述出来总是对的；判据复述出来才看得出它正要骗自己。
  • 验收的那一步，主动要求。有一处记录的原文是：若不是你要求，我本会跳过这一步。模型不会自发选择最疼的那步验证，它需要你点名。
  • 并行会话给不相交的所有权，然后让结构管纪律。五天证明的是后半句：结构就位后，不需要谁记得要小心。
立论 · 五日版的收束

甲活在字节、发布与客户双击的脚本里；乙活在卷宗、守卫与机制级判断里；丙用一天学会了两边的活法，顺手发明了第三边。让系统变好的，仍是那个动作：一个现场事实变成一道闸门。五天里它发生了更多次，而且现在闸门也会被验。两个解法依旧不需要更强的模型。需要有人把不信任搭成结构，然后让结构自己站住。
