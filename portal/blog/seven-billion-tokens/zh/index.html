七十亿 token 的
全程拆解。

一个业务意图、七个月、十一种记录用量的 agent harness——以及一个在三个方向上同时出错的已发表数字。

意图过程方法模型归因四个维度

写给所有想用 AI 做业务的人。这是一个真实案例的完整解剖：同一个操作者、同一个业余无线电业务生态、七个月（2026-03 → 2026-09，另有一段 2025-10 → 2026-04 的对照期）、七个代码仓库、十一种会记录用量的 agent harness、十几种模型。全文只回答一条主线：业务意图如何一步步变成交付物，「来来回回」了多少次、为什么越来越顺，以及支撑这个故事的每个数字到底能承担什么。每个数值都带来源与截止时间，事实与推断分开标注；完整的账本表与测量边界放在分册里，这篇文章只做叙事。

TL;DR——五条结论拿到骨架

  • 事实一本账可以同时虚高和虚低。已发表的 7,007,437,567 个 token 既虚高（某个 harness 把同一 API 响应的分块重复计入，约 2.7 倍），又虚低（另一个被标为「未记录」的 harness，其实有 485,213,348 个 token 躺在一张没人查的表里）。诚实重跑的结果是 7,404,583,808。
  • 事实账本是读数，不是资产。某个 harness 在一周内删掉了自己的历史（少 679,899,086 个 token）；同一个脚本十二分钟后重跑，差额 51,427,037，因为做测量的那个会话本身也在被测量。
  • 事实效率曲线是真的。三条仓库曲线同向下降：ft8 每交付一个提交，人类介入轮次从 17.1 → 0.3（约 30 倍）；上周 mrrc_modern 在 41 个提交上维持在 0.73 轮/提交。
  • 推断模型能力定上限，方法决定你实际吃到多少。同一个模型在 ft8 探索期是 75.5 M/提交，维护期是 0.9 M/提交。两个变量里只有一个在你手里。
  • 论点一句话纪律：先问「我的判断沉淀在哪里」，再问「AI 能帮我做什么」——引用任何数字之前，先把它快照下来。

01 · 开篇

会倒退的账本

在讨论方法之前，先讲一条用代价换来的测量教训。

2026-09-05，本站发表了一份 token 台账：7,007,437,567 个已记录 token。一周后同一个测量重跑，结果是 7,404,583,808——多出 397,146,241。有意思的不是增长，而是旧数字同时在三个方向上都是错的。

方向发生了什么证据
虚高claude-code 的日志会为同一个 API 响应的每个分块各写一条 usage 记录，逐行求和会把总量放大约 2.7 倍。按 message.id 去重后只剩 818,520,401，整个账本也随之变成 5,695,506,675。6,600 个不同的 API 响应
虚低Hermes 曾被写成「未记录」。它记录得好好的——在 sessions 表里存着 485,213,348 个 token。上一次的检查查的是 messages.token_count，那一列全是 0。292 个会话，2026-05-15 → 07-24
漂移claude-code 在 2026-09-07T13:13:57Z 删掉了自己较早的日志，同一个 harness 因此比一周前少计 679,899,086 个 token。紧接着，同一个脚本十二分钟后重跑，又差了 51,427,037——因为执行这次测量的会话本身，正在往被测量的日志里写东西。观测者效应，复现两次

反向校验和这个发现同样重要。codex 自八月下旬起停用，它的数字两次测量逐位相同：547,796,667——而且是用两条不同的代码路径算出来的。稳定的读数和不稳定的读数都是信息，但只有稳定的那个才配叫「总量」。

事实

本页所有数字都是 2026-09-12T02:40:59Z 这一时刻的快照，覆盖十一种 harness。逐 harness 的完整表格、每个 harness 各自的测量窗口、以及「什么可以比、什么不可以比」的规则，都在分册《账本与测量边界》里。已记录账与估算账不合并：iFlow 那约 2.47 亿 token 是按字符数估算的（它的用量字段全为零），不计入本页任何合计。

论点

证据必须被快照，不能被累计。一个没有截止时间的数字不是测量结果，是一个带小数点的传言。

卷一 · 业务与需求

意图从不以「AI」开头

这个生态的每个产品都起于一句业务语言的话，且去掉「AI」这个词后依然成立。

论点

第一条规律：如果业务诉求离开 AI 就不成立，那它不是业务诉求，是技术 demo。

03 · 对照组

六个月，知识没有载体

模型并不弱，弱的是知识没有载体。

2025-10-20 至 2026-04-16，同一个人用 iFlow 做了 185 个会话、37,202 轮对话，换了 6 个模型后端（qwen3-coder-plus、glm-5——单周就有 10,420 轮——kimi-k2.5、minimax-m2.5）。产出是真实的：MRRC 的祖先就出在这里。但没有任何东西留得下来。

事实

37,202 轮对话的用量字段全部为零，且没有任何工程产物留下：无契约、无文档体系、无门禁。会话结束，这一轮学到的东西随之消失。

这就是卷三一切机制要解决的问题。

卷小结

意图以业务语言存在，否则不成立；知识需要一个比对话长寿的载体。后面各卷的一切机制，都是为了后半句。

卷二 · 过程

从「来来回回」到「一次做对」

「越来越顺」是感觉，量化才是证据。三个指标，全部能从 git 历史与本机日志复核。

06 · 返工

不是单调下降，而是「弧形」

返工集中在探索/整合周，维护周个位数。

事实

ft710 的 fix 提交占比从开坑周 36% 降到维护周 6–12%；ft8 从 29% 降到 17%——且是在提交量最大的两周（147 / 82 个提交）做到的。

反面证据同样真实，而且这一周就来了。MRRC 在大整合周（W32，7.98 亿 tokens）fix 占比 50%；modern 在大重构周（W35）31%；sunsdr 早期硬调周 51%。上一周 mrrc_modern 落了 41 个提交，其中 17 个是 fix——fix 占比 41%，是重构周以来的最高值。新需求永远带来新返工。区别在于返工由谁完成：人只介入了 0.73 轮/提交，也就是说这些返工几乎全部由 agent 自主完成。

07 · 节奏

工作流的成型

契约测试先红，agent 交付到绿。

事实

发布还在加速：这一周 mrrc_modern 从 v1.14.0 一路发到 v1.14.3——五天四个版本，而且版本自己的 changelog 在发布当天就被纠正。更早：modern 13 天 6 版（一天 3 版）；ft8 诞生周 3 天 3 版；MRRC 曾两天 9 版。

事实

website 仓从 2026-W35 起出现稳定的「契约测试先红、功能提交转绿」模式：5 次 test→feat 对，转绿中位 19 分钟。本系列文章自己也是用这套流程写出来的。

推断

先写契约、AI 交付到绿——这是后期才成型的制度化能力，也是「顺」的组织化形态。

卷小结

三条曲线同向下降；返工呈弧形、集中于探索周。后期的区别不是零返工，而是返工由谁完成——agent 自主完成。

harness 与 SDD 在各阶段的作用

方法的长成在 git 时间线精确可查；它最硬的证据，是一条从现场事故出发的链。

方法的长成

这套机制的分工：外层 harness 定义业务/技术/产品约束（为什么做、边界在哪、什么证据能改变结论）；内环 Specify → Implement → Test → Review → Observe → Update SDD 整个委托给 agent；活体 SDD 让设计意图向下流、现场证据向上回流，生命周期状态显式标注、无自动晋级。

09 · 事故链

方法有效性的最硬证据

52 条约束没有一条是事先聪明地设计的，全部能追溯到具体事故。

FT-710 频率漂移 · 13 天闭环

DN; 不是 DNR 查询而是 VFO 步进命令，每 2 秒轮询一次会让实机频率每次漂移约 20 Hz——现场事故（07-07 修复 72fd6f0）→ 设计裁决 AD-014 入 SDD（07-08 bb128ff）→ 机器可读约束 cat-no-dn（07-20 2498ec2）→ 编辑前拦截可复现（退出码 2）。

部署备份打满磁盘 · 7 天闭环

08-29 服务器 /var/tmp 到 100%（单份备份约 300 MB）→ 09-05 四个仓库同日姊妹修复，并顺藤挖出「portal 备份从未生效」的隐藏缺陷（远程 heredoc 未加引号，067f565）→ 规则升级为四条部署铁律。

论点

事故转化率——从事故到永久免疫的时间——是组织学习能力的真正度量。本生态跑在 13 天和 7 天。一个停止增长的注册表不自动等于好消息：它是一个问题，答案在下次事故发生时有没有新增条目。

10 · 交付证据

两本永不相交的账

2026-09-12 普查当天实跑，不是引用旧记录。

事实

FT-710：439 passed。mrrc_modern：724 passed，比一周前的 682 多。ft8：935 passed, 1 skipped, 1 xfailed——此前发表的是「937 collected」，而 collected ≠ passed，措辞必须随证据改。另外：三个产品仓库都已迁到各自的虚拟环境（Python 3.13），再用系统 Python 3.9 跑测试会在收集期因 X | None 注解直接报错。这是环境限制，不是产品缺陷——边界要写下来，而不是悄悄丢掉。

A 账 · 产品成熟度

  1. 设计目标
  2. 仿真
  3. 自动化测试
  4. 台架验证
  5. 现场验证
  6. 发布运营
  7. 已知缺陷（诚实的一级）

B 账 · 过程证据

  1. 注册表有条目
  2. 有规格 / 计划轨迹
  3. 会话中被强制执行
  4. 拦截被复现验证

两本账不相交：B 账再漂亮也不为 A 账背书。开放边界如实保留：FT710Mobile 有一个未解决的 P0 PTT 安全问题；EFHW 调谐器在 PCB 打样与台架验证之前，声明状态停在设计目标。

论点

可以委托「做」，不能委托「算不算」。责任不能委托。

卷小结

方法不是事先设计出来的，是从事故里长出来的。裁决 → 机器可读约束 → 写前拦截是闭环；52 条约束条条可溯源到具体决策或事故，而不是某次规划会。

卷四 · 模型

模型不是长期变量

七个月、六个时代，以及让整个问题变小的一周。年鉴另立分册。

11 · 主力切换

主力在一周之内换了

本机日志实测，非厂商宣传。

2026-09-05，这个生态的 claude-code 工作负载由一个性价比档模型主导。七天之后，同一个 harness 已经被另一个模型接管：qwen3.8-max-0902 达到 3,883 次调用，而上一任主力仍在日志里，但已不再驱动工作。pi 那一侧，一个在上次普查里根本没出现过的模型——glm-5.3-flash——已经跑到 745 次，还多了一个视觉变体。

推断

此前的「flash 霸权」内部一直在轮换挑战者，而且轮换没有停——它在加速。模型市场每三到四周换一轮血。任何把模型名写死的方法，都是在买入一个会折旧的资产；耐久的部分是选型机制，不是某一次选择。

实测的分工依旧成立——旗舰模型买方向，性价比模型买执行，长上下文变体买专项，harness 买工作方式——而逐时代的完整记录、任务 × 模型 × harness 匹配表、公开评测（独立测评与厂商口径分层存放），以及路由标签的陷阱，都在分册《模型 × harness 年鉴》里。

卷小结

一个 harness 的主力可以在七天内换人。不要锁定模型，锁定你选模型的方式——并保留你自己的日志，因为那是唯一在测量你工作的评测。

卷五 · 归因与建议

效率究竟从哪里来

两个变量七个月里同时在变，这里是分离它们的证据。

12 · 归因

模型变强，还是方法变厚？

四条证据分离这两个变量。

1 · 同一模型，有无方法，差一个量级

flash 在 W32 探索 ft8 是 75.5 M/提交，同一模型在维护期是 0.9 M/提交。模型没变，变的是契约厚度。

2 · 模型不弱的时代，方法缺位照样归零

iFlow 期的 glm-5 单周 10,420 轮产出，但 37,202 轮零沉淀——方法缺位时，模型强弱无关宏旨。

3 · 方法成型的时刻精确可见

契约包 07-20 在 ft710 长出，08-02 被 ft8 整包继承，ft8 的介入轮次从 17.1 直降到 0.3。

4 · 模型升级改变的是「可委托半径」

单轮对话能可靠交付的任务粒度，从「改这个函数」长到「按这份规格交付功能并通过契约测试」。模型决定什么可以委托；方法决定委托出去的能不能收回来。

结论 · 推断

归因比例无法从本数据精确分离，但方向明确：模型能力决定上限，工程方法决定你实际吃到上限的多大比例。两个变量里只有一个在你控制之内。

13 · 建议

双轨建议

工程能力轨是你控制的，模型能力轨是市场给的；复利在前者。

工程能力轨（你控制的，复利在这边）：

  1. 先快照，再引用

    任何你打算据此行动的数字，都要带截止时间与明写的窗口。本文的账本盖的是 2026-09-12T02:40:59Z，而且每个 harness 带自己的窗口——因为其中一个会删掉自己的历史。

  2. 先写验收条件，再写第一行代码

    「算不算完成」的标准先于实现，是「来来回回」的第一大杀手。

  3. 让约束机器可读、写前拦截

    修复只是第一环，裁决 → 约束 → 门禁才是闭环（本生态：13 天 / 7 天）。

  4. 先红后绿

    契约测试先行、agent 交付到绿，本生态中位闭环 19 分钟；注册表走平这件事是被盯着的，不是被假设的。

模型能力轨（市场给的，策略是不锁定）：

  1. 按任务选档，不按信仰选型

    开荒/攻坚用旗舰，日常用性价比档，长上下文用专项变体；实测中没有任何模型在所有任务上占优，而这一周主力就换了人。

  2. 每 3–4 周重新评估一次模型市场

    本文时间线里主力换了六代；选型机制（快速试炼 + 按周复盘）比任何一次选型都重要。

  3. 警惕模型名

    路由标签不等于模型实体，官方宣称不等于独立测评；你自己的日志（什么任务、多少 token、几次来回、结果如何）是唯一不会骗你的评测。

把这七条建议变成「周一就能照抄」的东西——三类清单、三个模板，以及一份全部来自真实事故的失败模式库——都在分册《实践手册》里。

14 · 收束

先问判断沉淀在哪里

七个月的全部教训收进一句话。

论点

先问「我的判断沉淀在哪里」，再问「AI 能帮我做什么」。

没有载体的 AI 使用是消费——37,202 轮对话可以什么都不留下；有载体的使用是资产积累——每次事故、每条约束、每份规格都在为下一次委托降低成本。账本也是同一个道理：快照过、标注了时间的数字是资产；靠记忆引用的数字是天气。模型每个季度换一代，契约每天都在变厚。前者是天气，后者是气候。你能建设的是气候。

卷小结

模型决定上限，方法决定兑现比例。而测量本身服从同一条规律——不快照、不标时间，它就会在你脚下悄悄改变。

卷六 · 四个维度

把判断从执行中分离

提炼层。四个维度解释台账里发生的一切——也适用于任何业务，与无线电无关。

15 · 四个维度

四个维度，四条纪律

提炼层：台账合上之后，这个案例到底说明什么。

一句话方法

智能体工程不是「用 AI 写代码」，而是把判断从执行中分离：判断沉淀为契约，执行委托给 agent，证据决定契约的存亡。这一句话解释了为什么同一个操作者在对照期只留下蒸发的聊天记录，在测量期留下七个仓库与 52 条机器可读约束——差别从不在模型，在于判断有没有一个比对话更长寿的载体。

一 · 工程史：抽象阶梯的又一次上移

机器码 → 汇编 → 高级语言 → 框架 → 云：每一代工具把一层「怎么做」委托给机器。智能体工程把「实现」整层委托出去，人剩下三件事：定义意图、划定边界、行使裁决。工作量随之转移——12 份设计规格 + 10 份实施计划写在代码之前；ft8 第一个实质提交在任何业务代码之前带入 AGENTS.md、15 章 SDD 与契约测试。定义先于实现。

二 · 认识论：载体决定知识的寿命

聊天记录随会话蒸发；文档会过期、会被跳过；机器可读约束 + 运行时门禁不需要被记得——它会在该出现时自己出现。52 条约束是 52 次判断的永生，换了六种 harness 一条没丢，因为载体在仓库里、与工具无关。事故转化率是组织学习能力的真正度量：本生态 13 天、7 天。

三 · 经济学：token 是不确定性的价格，缓存读取是租金

token 花费跟随不确定性密度，不跟随代码行数，峰值永远落在方向未定处。在三个有完整分列的 harness 里，缓存读取占全部已记录 token 的 93.7%——这是「上下文还没被切成机器可用的片段」所要长期支付的租金。降低消耗的方式不是少用 AI，是降低不确定性本身，并让必须重读的上下文变短。

四 · 责任：两本账，三件不可委托的事

产品成熟度与过程证据是两本永不互证的账：普查当天 439 个全过的 FT-710 测试，关不掉客户端一个开放的 P0 PTT 安全问题。三件事永远不可委托——硬件打样与台架调试、实台 RF 安全、「证据是否充分」的裁决。不是因为 AI 不够强，而是责任不能委托。

四条纪律

1 · 定义先于实现——验收条件、非目标、边界写在第一行业务代码之前；意图用业务语言表达，去掉「AI」依然成立。2 · 事故必须变成规则——修复只是第一环；裁决 → 约束 → 写前拦截才是闭环。3 · 盯着不确定性花钱——token 峰值是方向雷达；重要数字双源对账，并且快照标时。4 · 两本账分开记——过程徽章永不提升产品声明；「做」可以委托，「算不算」永远在你手里。
