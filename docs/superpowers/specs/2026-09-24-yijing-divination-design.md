# 易占（yijing/）—— 基于《周易》的命理推断 Web 应用 · 设计规范

日期：2026-09-24
状态：已由用户批准设计

## 1. 背景与目标

vlsc.net 仓库新增一个纯静态子站 `yijing/`，上线于 `https://www.vlsc.net/yijing/`。
核心功能：以《周易》铜钱摇卦法起卦，排出本卦、之卦（变卦）、互卦，按朱熹《易学启蒙》
断法取断辞，引《周易》经传原文（卦辞、爻辞、彖传、象传）配白话今译，给出针对问事
类别的推断要点。

非目标（YAGNI）：

- 不做八字命理、不做纳甲六亲六神（后续可扩展）；
- 无后端、无账号、无分享功能；
- v1 仅中文界面，英文镜像留作后续。

## 2. 技术约束（继承仓库铁律）

- 纯静态 HTML/CSS/JS，无框架、无构建步骤、无第三方依赖；
- 部署为 tar 包直传 webroot，工具脚本（check_hexagrams.py、deploy.sh）不进包；
- 目录与 `efhw/` 同级：`yijing/`。

## 3. 页面流程（单页应用，三屏 + 历史面板；排卦与断卦同处「卦成」屏）

1. **问卦**：文本框输入所问之事；类别选择（综合/事业/财运/感情/健康/出行）。
2. **摇卦**：点击"摇卦"，三枚铜钱 CSS 动画，共六次；每次显示该爻结果
   （老阳 ⚊○ / 少阳 ⚊ / 少阴 ⚋ / 老阴 ⚋×），自初爻至上爻逐爻累成卦画。
3. **排卦**：完整卦画（CSS 绘制阴阳爻），标注：本卦卦名、上卦/下卦（经卦名与
   取象）、动爻、之卦卦名、互卦卦名。
4. **断卦**：
   - 按朱熹断法取断辞（规则见 §5）；
   - 展示经文原文（卦辞/爻辞/彖传/象传相应条目）+ 白话今译；
   - 按问事类别给出要点提示（每类一断语模板，为贴合卦义取象的简述，
     非规则引擎；卦卡另展示上下经卦的五行与方位）；
   - 综合断语一段。
5. **存档**：每次占断自动存入 localStorage（最多保留 50 条）；历史面板可回看、
   可清空。localStorage 不可用时静默降级，不报错。

## 4. 架构与文件结构

```
yijing/
├── index.html              # 单页：问卦/摇卦/卦成三屏（排卦+断卦同在卦成屏）+ 历史面板
├── css/yijing.css          # 水墨宣纸风格；朱砂 #9e2b25 点缀；衬线字体栈
├── js/
│   ├── data/trigrams.js    # 八卦：卦名、卦符、五行、方位、家庭/身体等取象
│   ├── data/hexagrams.js   # 64 卦全数据（schema 见 §6）
│   ├── cast.js             # 起卦：三钱概率模型，返回六爻数组
│   ├── gua.js              # 排卦：本卦/之卦/互卦计算，动爻判定，朱熹断法取辞
│   └── app.js              # UI 状态机、铜钱动画、卦画渲染、localStorage 存档
├── check_hexagrams.py      # 数据完整性校验脚本（部署前验证门）
└── deploy.sh               # 仿 efhw/deploy.sh；排除 check_hexagrams.py 与自身
```

模块边界：

- `cast.js` 只做随机起卦，输入无，输出六爻数组（每爻 6/7/8/9）；
- `gua.js` 纯函数库：六爻数组 → {本卦, 之卦, 动爻[], 互卦}，及断辞条目选择；
  不碰 DOM；
- `app.js` 唯一的 DOM/状态层，调用 cast/gua 取数据渲染。

## 5. 起卦与断卦规则

**起卦（三枚铜钱）**：每爻掷三钱，正面 3 反面 2，合计：
6 = 老阴（动，概率 1/8）、7 = 少阳（3/8）、8 = 少阴（3/8）、9 = 老阳（动，1/8）。
掷六次，初爻在下。

**排卦**：

- 本卦：六爻阴阳（7/9 为阳，6/8 为阴）；
- 之卦：动爻阴阳互变后所得卦；无动爻则无之卦；
- 互卦：取本卦二三四爻为下卦、三四五爻为上卦。

**断法（朱熹《易学启蒙》）**：

| 动爻数 | 取辞 |
|---|---|
| 0 | 本卦卦辞 |
| 1 | 本卦动爻爻辞 |
| 2 | 两动爻爻辞，以上爻为主 |
| 3 | 本卦与之卦卦辞，本卦为主 |
| 4 | 之卦中两不变爻爻辞，以下爻为主 |
| 5 | 之卦不变爻爻辞 |
| 6 | 之卦卦辞（乾用九、坤用六相应条文） |

## 6. 数据模型

`trigrams.js`：`{ 名, 符号(3位二进制字符串), 五行, 方位, 自然取象, 家庭取象 }` × 8。

`hexagrams.js`：数组 × 64，按通行本卦序：

```js
{
  id: 1,                    // 卦序 1–64
  name: "乾",
  fullName: "乾为天",
  upper: "乾", lower: "乾", // 经卦名
  lines: "111111",          // 初爻在前，1 阳 0 阴；与 id 的对应由校验脚本保证
  guaci: "元亨利贞。",
  tuan: "彖曰：……",
  xiang: "象曰：天行健，君子以自强不息。",
  yaos: [                   // × 6，初爻在前
    { title: "初九", ci: "潜龙勿用。", xiang: "象曰：……", baihua: "……" }
  ],
  yong: { ci, xiang, baihua } | null,  // 乾用九、坤用六，其余 null
  guaciBaihua: "……",       // 卦辞白话
  advice: {                 // 问事类别要点提示
    综合: "…", 事业: "…", 财运: "…", 感情: "…", 健康: "…", 出行: "…"
  }
}
```

经文原文为公版古籍文字；白话今译与 advice 为本项目新撰。

## 7. 视觉设计

- 底色仿宣纸（米白 #f5f0e6 一类），墨色正文，朱砂 `#9e2b25` 作标题点缀与印章元素；
- 字体栈：`"Songti SC", "STSong", "SimSun", serif`；
- 卦画：CSS 绘六爻横线，阳爻实线、阴爻中断、动爻加 ○/× 标记；
- 铜钱：CSS 圆形方孔样式，摇卦时翻转动画；
- 移动端可用：单列布局，断卦区可滚动。

## 8. 错误处理

- 数据缺失（某卦/某爻字段为空）：断卦区显示"经文数据缺失"占位，不中断流程；
- localStorage 抛出异常（隐私模式）：捕获后跳过存档，界面不提示错误；
- 未输入所问之事也可起卦（视为"心中默念"）。

## 9. 测试

`check_hexagrams.py`（Python 3 标准库，仿 `efhw/check_baluns.py` 的验证门模式）断言：

- 恰好 64 卦，id 1–64 无缺无重；
- 每卦 lines 恰 6 位且仅含 0/1；lines 与（上卦, 下卦）经卦组合一致；
- 每卦恰 6 条爻，爻题正确（初/二/三/四/五/上 + 九/六）；
- 乾（id 1）有 yong（用九）、坤（id 2）有 yong（用六），其余卦 yong 为 null；
- 所有 guaci/tuan/xiang/baihua/advice 六类字段非空。

校验脚本解析 `hexagrams.js`（正则提取后用 JSON 兼容解析或经 Node 导出为 JSON，
取实现简单者）。CI 无；作为本地验证门，deploy.sh 前置调用。

## 10. 部署

`deploy.sh` 仿 `efhw/deploy.sh`：前置运行 `check_hexagrams.py`，失败即中止；
tar 打包时排除 `check_hexagrams.py`、`deploy.sh`、`.DS_Store`；
目标 `/var/www/vlsc.net/yijing`。nginx 现有配置（vlsc.net.conf）按目录服务，
无需新增 server block——实施时确认即可。
